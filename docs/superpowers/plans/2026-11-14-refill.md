# refill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build refill, a small installable browser app that counts the 20cl water bottles Sophie drinks at work, with two daily reminders and a month history.

**Architecture:** Static files served from the repo root by GitHub Pages: one `index.html`, plain CSS and native ES modules, no build step and no framework. Pure logic (settings, days, reminders, storage) lives in `src/core/` and is unit-tested with Node's built-in test runner. The UI in `src/ui/` renders into the DOM and is covered by Playwright smoke tests against a tiny local server.

**Tech Stack:** HTML, CSS, JavaScript ES modules, `localStorage`, Notifications API, service worker + web app manifest; Node 22 `node:test` for tests; Playwright 1.63 (pre-installed, loaded with `createRequire`) for smoke tests.

**Spec:** `docs/superpowers/specs/2026-11-14-refill-design.md`. The clickable demo `docs/superpowers/specs/refill-demo.html` is the visual reference: reuse its pixel bottle, star, palette tokens and calendar styling.

## Global Constraints

- No build step, no framework, no runtime dependencies. The repo root is the site.
- Data stays in the browser (`localStorage`). Nothing is sent anywhere.
- Never draw the brand name or logo on the bottle.
- Layout fits a window about 360px wide; follows light and dark mode.
- Reminders only Monday to Friday, only while the app is open.
- Defaults: schedule 3 / 2 / 3 (goal 8), bottle 20cl, morning check 11:00 on, day total 16:00 on.
- Use the words in `CONTEXT.md` (bottle, logged, daily goal, schedule, part, extra bottle, reminder, morning check, day total, fixing a day) in code names and UI copy.
- Each roadmap entry is built on its own branch `entry-<slug>` and merges only on Sophie's go.

## Review Focus

1. The app stays open overnight: at midnight the tracker switches to the new day at 0 without a reload (Task 7).
2. Logged count above the daily goal, then the goal is lowered in settings: every logged bottle still shows, none disappear (Tasks 1, 4).
3. `localStorage` throws or holds corrupt JSON: the app starts with defaults instead of a blank page (Task 2).
4. The PC was off at 11:00: opening at 11:30 fires the morning check once, opening at 12:05 does not, and a reload after it fired does not fire it again (Tasks 6, 7).
5. Notifications blocked or unsupported: settings says so and nothing throws (Task 7).

**Interfaces:**
- Produces (`src/core/settings.js`):
  - `DEFAULT_SETTINGS = { parts: { morning: 3, lunch: 2, afternoon: 3 }, bottleCl: 20, morningCheck: { on: true, time: "11:00" }, dayTotal: { on: true, time: "16:00" } }`
  - `goal(settings) -> number`: sum of the parts.
  - `withGoal(settings, n) -> settings`: `n` clamped to 1..20; the afternoon part absorbs the difference; if `n` is below morning + lunch, take from lunch first, then morning.
  - `withPart(settings, part, n) -> settings`: `n` clamped to 0..10; returns `settings` unchanged if the goal would become 0.
  - `withBottleCl(settings, cl) -> settings`: clamped to 5..150.
  - All return new objects; inputs are never mutated.
- Produces (`src/core/days.js`):
  - `dateKey(date: Date) -> "YYYY-MM-DD"` in local time.
  - `countOn(days, key) -> number` (0 when missing).
  - `tapBottle(days, key, index) -> days`: index below the count unlogs the last bottle, otherwise logs one more.
  - `slots(count, goal) -> number`: `max(goal, count)`, plus 1 extra bottle slot once `count >= goal`.
  - `litres(count, bottleCl) -> number`.
  - `shade(count, bottleCl) -> 0..4`: 0 L → 0, ≤0.6 L → 1, ≤1.2 L → 2, <2.0 L → 3, ≥2.0 L → 4.
  - `reachedGoal(before, after, goal) -> boolean`: `before < goal && after >= goal`.

**Interfaces:**
- Consumes: `goal`, `dateKey`.
- Produces: `dueReminders(now: Date, settings, count, fired) -> { due: Array<{ id: "morningCheck" | "dayTotal", message: string }>, fired }`.
  Rules: Monday to Friday only; a reminder is due when it is on, `now` is at or after its time and less than 60 minutes after it, and it has not fired today (`fired.date !== dateKey(now)` resets both flags). The morning check is marked fired but produces no message when `count >= parts.morning`.
  Copy, exact:
  - morning check: `` `${left} more bottle${left === 1 ? "" : "s"} to stay on track this morning (${count} of ${morning}).` ``
  - day total, below goal: `` `You drank ${count} out of ${goal} bottles.` ``
  - day total, goal reached: `` `${count} out of ${goal} bottles 🎉 Goal reached!` ``
